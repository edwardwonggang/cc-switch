# Codex 内置统一供应商

Codex 供应商列表始终置顶显示内置卡片 **Codex**（固定 ID：`codex-unified`）。用户只勾选已有供应商，再点击“使用 Codex”；不创建或命名新卡片，不填写凭证、模型或映射。勾选自动保存，失败恢复原选择。普通供应商的“使用”入口保留，用户可随时明确切回。

## 使用

1. 在 Codex 供应商列表顶部打开 **Codex → 选择供应商**。
2. 勾选已有来源。右侧自动预览 `A-deepseek-v4-flash`、`B-deepseek-v4-flash` 等模型，不需要手动映射。
3. 点击 **使用 Codex**。需要回退时，直接点击任一原供应商的使用入口。

## 路由与存储

- 首次展示只生成只读卡片，不写数据库，也不自动切换当前供应商。成员保存于该卡的 `settingsConfig.memberProviderIds`，`meta.providerType=codex_unified`；真实供应商配置仍为唯一来源。
- 统一卡写入 Codex `config.toml` 的身份固定为 `model_provider = "custom"` 与 `[model_providers.custom]`，与普通供应商一致。Codex 按该身份对历史分桶，不能为统一卡另起供应商身份而让既有历史不可见；CC Switch 的固定卡数据库 ID 仍为 `codex-unified`。这里不迁移或改写既有历史数据库与 rollout。
- 既有模型目录优先读取 `settingsConfig.modelCatalog.models[].model`，无目录才取该供应商明确配置的默认模型。
- 对外模型别名为“供应商名称-真实模型”，保留大小写、中文和横线，名称空白归一为横线。完整别名冲突时，每个冲突来源自动加稳定身份短后缀，并在预览中展示。
- 路由优先查询完整别名，得到精确成员 ID 和真实模型；从不拆横线猜身份，也不把别名发给上游。未命中别名时，仅按当前已勾选成员声明的 `actual_model` 完整字符串精确匹配；只有唯一来源才兼容旧会话的裸模型。同名多来源、未知、已取消勾选或失效模型直接报错，不转发、不自动换供应商。完整别名优先级高于另一成员恰好同名的真实模型。
- 模型目录逐成员生成，保留各自上下文、推理档位、工具协议和官方指令。成功请求不修改全局当前卡片，避免不同成员并发相互改配置。
- 选择统一卡会复用并启用现有 Codex 本地接管。统一卡使用期间不能清空全部有效成员或关闭所需代理；需要停用时先手动切回普通供应商。不会自动替用户选择某一家。
- 已勾选成员不能直接删除，需先取消勾选。活动成员编辑与目录投影在同一切换锁内提交，失败恢复原记录、配置、目录和备份，不回滚独立登录凭证。
- 模型探测只返回候选；保存探测结果后，活动成员更新和统一卡成员勾选都会复用同一 `live_settings` 生成器重建 live 配置及恢复备份，保持 `custom` 历史身份。此约束已由 e24 的共享常量实现；仍运行旧EXE时，手动改配置可能被旧生成器写回，须部署带该修复的精确产物，不能靠重复改配置维持。
- 普通供应商、Claude/Gemini 等既有路由保持各自原策略，只有选中固定 Codex 卡片才解析统一别名。

接管恢复会保护当前客户端登录，并将供应商路由凭证与客户端 `auth.json` 分开处理；启动、同步和替换验收要求见 [Codex 接管恢复中的凭证边界](codex-auth-recovery.md)。

## 旧会话切换模型前的压缩

普通供应商创建的旧会话可能保存 `DeepSeek-v4-Flash-Thinking` 等裸模型名。切换统一卡并重启客户端后，在旧会话选择新的完整别名，也可能先向旧模型发起历史压缩。作为机制参考，官方 Codex `rust-v0.156.1`（提交 `b412ff32c417f855c2b2d1581b77058eed87c84b`）的 `codex-rs/core/src/session/turn.rs::maybe_run_previous_model_inline_compact` 明确使用 `previous_turn_settings.model`：压缩兼容哈希变化，或上下文已超过新模型窗口且发生窗口缩小，会在新模型采样前压缩旧上下文。重启不能消除持久历史的模型身份。该版本对应诊断CLI；实际VS Code扩展现场为`0.162.0-alpha.17.2`，不能把参考源码当成现场版本或唯一触发原因。

兼容旧名称只复用已勾选成员的真实模型声明，不改历史、会话或目录默认选择。唯一匹配继续使用旧模型所属成员和原凭证，失败也不跨来源；不会把旧模型压缩强制改发到新选择的 GPT。若两个成员都声明同一裸模型，必须使用完整别名，或另行建立可证明的历史来源绑定，不能按成员顺序猜测。

这项修复只解除本地别名解析阻塞。flow等实际上游是否支持当前压缩协议、输入长度和模型能力，仍须依据上游真实结果分别确认；解析成功不保证压缩或后续回合成功。

## 验证与发布

前端定向测试覆盖固定卡、无需填写、自动保存、同名模型双别名、无成员禁用、保存失败回滚及不自动切单供。后端隔离测试源码覆盖只读展示、成员生命周期、失败回滚、完整别名优先、唯一旧模型名称、普通及压缩请求的来源与凭证、歧义/未知/未勾选来源零出站、统一卡的 `custom` 历史身份与本地代理配置、混合 Responses/Chat 假上游及单供兼容。

前端使用 `pnpm typecheck`、`pnpm test:unit` 验证。后端编译、测试和 Windows 出包由仓库 GitHub CI 负责；本机格式检查只证明语法和格式，不能替代执行测试。构建、下载和部署必须对应同一提交 SHA，最终以该提交 CI 和部署后真实运行回执验收。
